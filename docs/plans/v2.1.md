### M2: `/arena`

#### What upstream is

`Jakeschincariol/arena-skill` at `df07b8e` (one commit; MIT, © 2026 Jake Schincariol): `SKILL.md`
(the orchestration and five prompt templates), `bracket.py` (1,235 lines, Python 3.8+ standard library
only), `strategies.json` (15 reasoning modes × 12 workflows × 12 strategies = 2,160 cards), `rubric.md`
(five weighted criteria) and 404 lines of unittests. N subagents get the same task and different
cards, then fight a single-elimination bracket: attack, defend and revise, judge. A run costs 6N − 5
subagent calls, plus one when there is a rejected answer to beat: 43 for 8 agents, 91 for 16, 595 for
the default 100. Every agent writes to `.arena/` and replies in one line, and the state is one JSON
file, so a run survives compaction.

#### Why it fits

It already keeps several of Nonna's principles. The bookkeeping is code; the orchestrator never
judges; `bracket.py` does the arithmetic and enforces the fatal rule; every random choice is seeded
and the seed recorded; the main context holds receipts, not solutions; the winner is a proposal it
never applies. An arena is a search of the solution space, which
[ADR-0002](../adr/0002-llm-proposes-gates-decide.md) allows upstream of the gates, provided its output
still passes them.

#### Gated mode: the referee includes the suite

For a code task where a test command is recorded (`nonna.testCmd`, or a directory's own,
[ADR-0014](../adr/0014-a-test-command-per-directory.md)):

1. **The base is the working tree the agents read**, not `HEAD`: a snapshot of tracked changes and
   untracked files, taken before the spawn, so a diff written against a dirty tree applies.
2. **A baseline, not a precondition.** The suite runs once on the base and records which tests fail
   (`lib/tests.sh`'s failure digest). A red baseline is the normal case for a bug fix, and the gate
   judges candidates against it. Only a suite that cannot run at all stops gated mode, with a message.
3. **One gate job per revised solution a judge will read**, one Bash call each, so no call outlives
   the tool's ten minutes: 2N − 2 runs plus the baseline, 15 for 8 agents (one more when the rejected
   answer to beat carries a diff).
4. **Isolation.** Each job copies the base into a scratch tree outside the repository: a separate
   clone with its own `.git`, never a linked worktree, whose `.git` leads back to the user's. The
   ignored directories the suite needs (`node_modules`, `.venv`, build output) are made available
   read-only. The job applies the diff and runs the command(s) `lib/tests.sh` would choose inside an
   OS sandbox: no network, an `env -i` allowlist, writes only to the scratch tree. Where no sandbox is
   available (R8), gated mode is off and the run is rubric-only. As defence in depth, the job hashes
   `.git/hooks`, `.git/config` and `.git/nonna*` before and after, and any change halts the run. The
   scratch tree is removed when the job ends, and the run removes whatever is left.
5. **Fail-closed verdicts.** A candidate passes when no test that passed on the base fails and any
   tests the task names pass; for a runner whose output the digest cannot read, the whole suite must
   be green. Everything else fails: a diff that does not apply, a timeout (unlike Stop, where out of
   time is not red), a crash of the gate itself, an unreadable result, a secret pattern in the added
   lines. The judge phase does not start for a match whose gate result is missing.
6. **The decision.** `decide()` reads the result: fatal = the judge's fatal, or a failed gate. The
   judge sees the digest, scores what tests cannot see (requirements, design, clarity), and is told
   the suite's verdict is final. When every candidate failed, the report's first line says no
   candidate passed the suite.
7. With no test command, or no sandbox, the run is rubric-only, and the result says so in its first
   line.

The winner is still a proposal. `/arena` ends by offering `/tdd` to land it test-first, or `/review`
of its diff, and never applies anything itself.

## Appendix: two refusals to triage

On 2026-11-11 the branch guard refused two read-only compound commands with "branch guard: refusing
--no-verify and hook overrides". Their parts, run separately, passed, and so did smaller combinations
of `python3 -I -c`, a `grep` of a file under `.claude/hooks/` and a `git` read; run alone,
`git config --get nonna.testCmd` is allowed too. The refusal comes from a combination, so the triage
starts by minimizing it. The shapes:

```bash
cd /home/user/nonna && python3 -I -c "<a multi-line program>"; git config --get nonna.testCmd || echo "(unset)"; grep -nE 'STATUS' .claude/hooks/post-compact.sh | head; git diff --stat v2.0.0 origin/main -- CHANGELOG.md docs/STATUS.md
```

The second was the same without the `git config --get` reads, with
`git diff v2.0.0 origin/main -- CHANGELOG.md | grep -E '…' | cut -c1-150 | head -20` at the end.
